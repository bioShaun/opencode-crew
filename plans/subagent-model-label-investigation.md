## 用户需求

只在现有原生标签旁显示模型，例如 `Engineer Subagent - gpt-6.1-terra`。

- 不新增侧边栏。
- 不把模型拼进任务标题，不改变角色 ID。

- 优先展示实际子会话模型；不能把 Crew 配置值未经说明地当作实际模型。
- 用户曾看到类似显示，但具体界面、版本和配置未知。

## 已核实

- 当前宿主为 OpenCode 2.2.4，仓库依赖 `@opencode/plugin` 2.2.3。
- `src/index.ts` 分别设置角色的 `name`、`description` 与 `model`，没有实现原生子代理工具行的渲染。
- 已安装 SDK 的 `node_modules/@opencode/plugin/dist/tui/context.d.ts` 公开了通用 slot，包括 `sidebar.content`，未在检查的公开 slot 列表中找到 subagent 卡片专用插槽。这不等于证明宿主没有其他内部接口。
- 官方 TUI 文档将宿主 renderables 排除在插件稳定 API 之外：<https://opencode.ai/v2/docs/build/plugins/cli>。
- 当前可见的 subagent 工具允许显式传入 `model`。是否因此在用户当前 TUI 原位显示模型，尚未实测。
- 没有找到可核实且适用于当前安装版本的“原位追加模型名”配置项。

## 尚未核实的线索

只读调查代理报告了官方仓库搜索摘录中的线索：原生工具行可能只显示调用时显式传入的模型；另有 `SubagentFooter` 可能读取 assistant 消息中的实际模型数据。

但本轮未取得可复核的 2.2.4 对应 renderer 源码、固定版本链接或本机渲染验证。因此这些仅作为后续检索方向，不能作为已确认的当前版本行为，也不能据此断言插件绝对无法实现。

当前未检查本机二进制的嵌入渲染代码，也未验证用户提到的标签是父会话工具行还是进入子会话后的 footer。
